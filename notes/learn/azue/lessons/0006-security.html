Lesson 6: Security — SAS, RBAC, Managed Identity & Network Security

Estimated time: 20–25 minutes  |  Focus: Authentication, Authorization, Network Isolation

🎯 What you'll learn
How to secure Service Bus using Microsoft Entra ID with managed identity (recommended), when to use Shared Access Signatures (SAS), how to lock down the network with private endpoints and IP firewall, and how to configure these in Spring Boot.

The Security Hierarchy: What Microsoft Recommends

🥇 Microsoft Entra ID (RBAC) — Best. Uses Azure AD tokens, no keys to manage, full audit trail, supports managed identities.

🥈 Shared Access Signatures (SAS) — Good fallback. Key-based, time-limited tokens, fine-grained scoping to entities.

🥉 Connection strings with keys — Simplest but least secure. Avoid in production when possible.[source]

Method 1: Connection String with SAS Key

The simplest approach. A connection string embeds the key directly. Works everywhere but has the security issues of a shared secret.

application.yml
spring:
  cloud:
    azure:
      servicebus:
        connection-string: Endpoint=sb://mysb.servicebus.windows.net/;SharedAccessKeyName=RootManageSharedAccessKey;SharedAccessKey=abc123...
// Java: connection string in the builder
new ServiceBusClientBuilder()
    .connectionString("Endpoint=sb://...;SharedAccessKeyName=...;SharedAccessKey=...")
    .sender()
    .queueName("orders")
    .buildAsyncClient();
⚠️ Risks: The key gives full access to whatever the SAS policy grants. If leaked, an attacker has that access until the key is rotated. No audit trail tying operations to specific users. Use only for local dev or when Entra ID isn't feasible.

Method 2: Microsoft Entra ID (Recommended)

Use Azure AD authentication with DefaultAzureCredential — it chains through multiple authentication sources automatically: Managed Identity (in Azure) → Environment Variables → Azure CLI → VS Code → Interactive Browser.[source]

Java Code with Managed Identity

// Fully qualified namespace (no key!)
String fullyQualifiedNamespace = "mysb.servicebus.windows.net";

// DefaultAzureCredential chains: ManagedIdentity → Azure CLI → etc.
DefaultAzureCredential credential = new DefaultAzureCredentialBuilder().build();

ServiceBusSenderAsyncClient sender = new ServiceBusClientBuilder()
    .fullyQualifiedNamespace(fullyQualifiedNamespace)
    .credential(credential)
    .sender()
    .queueName("orders")
    .buildAsyncClient();

Spring Boot with Managed Identity

application.yml
spring:
  cloud:
    azure:
      servicebus:
        namespace: mysb
        credential:
          managed-identity-enabled: true   # uses system-assigned managed identity
      profile:
        tenant-id: ${AZURE_TENANT_ID}
      client-id: ${AZURE_CLIENT_ID}        # for user-assigned managed identity

# Or use the generic passwordless approach:
spring:
  cloud:
    azure:
      servicebus:
        namespace: mysb.servicebus.windows.net
        passwordless-enabled: true          # uses DefaultAzureCredential chain
🧭 Pro tip: In local development, DefaultAzureCredential will try Azure CLI first. Run az login and you're authenticated locally with the same code that uses Managed Identity in production. Zero code changes between environments.

Method 3: SAS Tokens (Granular, Time-Limited)

When you need to grant limited access to specific entities for a short time — without sharing keys: generate a SAS token server-side and give it to the client.[source]

// Service-side: generate a SAS token for a specific entity
import com.azure.core.credential.AzureSasCredential;
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;
import java.net.URLEncoder;
import java.nio.charset.StandardCharsets;
import java.time.Instant;
import java.util.Base64;

public class SasTokenGenerator {

    public static String generateSasToken(
            String resourceUri,    // e.g., "https://mysb.servicebus.windows.net/orders"
            String keyName,        // SAS policy name
            String key,            // SAS policy key (Base64)
            Duration validity) {

        long expiry = Instant.now().plus(validity).getEpochSecond();
        String stringToSign = URLEncoder.encode(resourceUri, StandardCharsets.UTF_8)
            + "\n" + expiry;

        Mac hmac = Mac.getInstance("HmacSHA256");
        hmac.init(new SecretKeySpec(Base64.getDecoder().decode(key), "HmacSHA256"));
        String signature = Base64.getEncoder()
            .encodeToString(hmac.doFinal(stringToSign.getBytes(StandardCharsets.UTF_8)));

        return String.format(
            "SharedAccessSignature sr=%s&sig=%s&se=%d&skn=%s",
            URLEncoder.encode(resourceUri, StandardCharsets.UTF_8),
            URLEncoder.encode(signature, StandardCharsets.UTF_8),
            expiry, keyName);
    }
}

// Client-side: use the SAS token
AzureSasCredential sasCredential = new AzureSasCredential(sasToken);
ServiceBusSenderAsyncClient sender = new ServiceBusClientBuilder()
    .fullyQualifiedNamespace("mysb.servicebus.windows.net")
    .credential(sasCredential)
    .sender().queueName("orders")
    .buildAsyncClient();

Network Security (Premium Tier)

FeatureWhat it doesTier
Private Endpoints Service Bus gets a private IP in your VNet. All traffic stays on Azure backbone — never touches the public internet. Premium only
Service Endpoints Restrict access to specific VNet subnets. Traffic still goes to the public endpoint but is filtered by source subnet. Premium only
IP Firewall Allow-list specific public IP ranges. IP firewall rules can be configured on Standard via ARM/CLI but portal UI is Premium-only. Premium (portal); Standard (ARM/CLI)
Disable public network access Completely block all public access — only private endpoints work. Maximum isolation. Premium only 
# Network lockdown via CLI
az servicebus namespace create \
  --resource-group myrg \
  --name mysb \
  --sku Premium \
  --public-network-access Disabled    # block all public access

# Create private endpoint
az network private-endpoint create \
  --resource-group myrg \
  --name mysb-pe \
  --vnet-name myvnet \
  --subnet private-endpoints \
  --private-connection-resource-id /subscriptions/.../namespaces/mysb \
  --group-ids namespace \
  --connection-name mysb-connection

Security Best Practices Summary

  1. Use Managed Identity (Entra ID) in production. No keys to rotate, no secrets in config files.
  2. Assign least-privilege RBAC roles. Senders get Data Sender, receivers get Data Receiver. Never use Owner for runtime apps.
  3. Disable local authentication (SAS keys) on the namespace if all clients support Entra ID.
  4. Use private endpoints for production Premium namespaces — keep traffic off the public internet.
  5. Rotate SAS keys regularly if you must use them. Use primary/secondary key slots for zero-downtime rotation.
  6. Never log connection strings or SAS keys. Use a secrets store (Key Vault).
  7. Enable diagnostic logging to audit who performed what operations.

Key Takeaways

  • Entra ID + Managed Identity is the gold standard. No keys, no rotation, full audit trail. Use DefaultAzureCredential for seamless local-to-cloud auth.
  • RBAC roles are granular. Assign Data Sender or Data Receiver, not Owner. Principle of least privilege.
  • SAS tokens are for external/limited access. Scope to specific entities, keep TTL short, generate server-side.
  • Network isolation needs Premium. Private endpoints, service endpoints, and disabling public access all require Premium tier.
  • Local dev vs. production — same code. DefaultAzureCredential handles the chain: Azure CLI locally → Managed Identity in Azure.
