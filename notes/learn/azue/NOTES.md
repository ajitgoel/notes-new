# Notes

## Learning Preferences
- Experienced with messaging: familiar with RabbitMQ, Kafka, SQS — understands queues, pub/sub, competing consumers
- Prefers conceptual understanding first, then hands-on code/CLI
- Building a real system in Azure
- **Primary language: Java with Spring Boot and Reactive programming (WebFlux/Reactor)**

## Teaching Style
- Don't re-teach messaging fundamentals
- Focus on what makes Service Bus different from other brokers they've used
- Use comparisons to RabbitMQ/Kafka/SQS where helpful
- Provide concrete decision frameworks (when to use X vs Y)
- Cite official docs for anything claim-based
- Code examples in Java with Spring Boot, using reactive patterns (Mono, Flux)
- Use `com.azure.spring:spring-cloud-azure-starter-servicebus` and reactive SDK where possible

## Lesson Cadence
- Keep each lesson tightly scoped to ONE concept
- Each lesson should take ~15-20 minutes
- End each lesson with a concrete skill/action
