Reactive Java Glossary

Project Reactor 3.x · Spring WebFlux · Azure Service Bus · Empower PMS
B
Backpressure
The mechanism by which a slow downstream subscriber signals an upstream publisher to slow emission. In Reactive Streams, implemented via Subscription.request(n) — the subscriber controls how many items it is ready to receive. Without backpressure, a fast producer can overwhelm a slow consumer causing OOM errors.
See also: Subscription, Publisher, onBackpressureBuffer
BlockHound
A Reactor tool (io.projectreactor.tools:blockhound) that instruments the JVM to detect blocking calls (e.g. Thread.sleep, JDBC) executed on non-blocking threads at runtime. Install in test profiles to catch violations early.
boundedElastic Scheduler
A Reactor scheduler backed by an elastic thread pool capped at 10× CPU count (default). Safe for blocking I/O — each blocking task gets its own thread. Use with Mono.fromCallable().subscribeOn(Schedulers.boundedElastic()) to wrap legacy blocking code.
See also: subscribeOn, parallel Scheduler
C
Cold Publisher
A publisher that starts a fresh execution for each subscriber. Each subscriber gets the full sequence independently. Most reactive data sources (DB queries, HTTP calls) are cold. Contrast with Hot Publisher.
concatMap
Like flatMap but subscribes to inner publishers sequentially — waits for each to complete before starting the next. Preserves order. Lower throughput than flatMap. Use when order matters and inner publishers can't run concurrently.
Context (Reactor)
Reactor's immutable, per-subscription key-value store — the reactive equivalent of ThreadLocal. Used to pass metadata (user ID, trace ID, tenant) through a pipeline without parameter threading. Access with Mono.deferContextual() and set with .contextWrite().
D
Dead Letter Queue (DLQ)
In Azure Service Bus, a sub-queue that holds messages that couldn't be processed successfully. In reactive consumers, call receiver.deadLetter(message) on processing failure rather than swallowing the error or crashing the consumer stream.
defer (Mono.defer / Flux.defer)
Creates a publisher lazily — the factory lambda runs per subscription, not at creation time. Critical when your publisher captures mutable state (e.g. current time, current user context). Mono.just(x) captures x eagerly; Mono.defer(() -> Mono.just(x)) captures it per subscription.
F
flatMap
The most-used reactive operator. Takes each item, applies a function returning a Mono or Flux, subscribes to each inner publisher concurrently, and merges results into the outer stream. Order is NOT guaranteed. Use flatMap(fn, concurrency) to bound parallel subscriptions.
See also: concatMap, flatMapSequential, map
Flux
Project Reactor's implementation of a reactive stream of 0..N items. Terminates with onComplete() or onError(). Implements the Reactive Streams Publisher<T> interface. Use for: collections, event streams, paginated results, SSE/streaming endpoints.
See also: Mono, Publisher
fromCallable
Mono.fromCallable(Callable<T>) — wraps a potentially blocking or exception-throwing supplier in a Mono. Unlike Mono.just(), the callable is NOT called at creation time but at subscription time. Always pair with .subscribeOn(Schedulers.boundedElastic()) if the callable blocks.
H
Hot Publisher
A publisher that emits items regardless of whether anyone is subscribed. Late subscribers miss past items. Azure Service Bus message streams, Sinks.Many multicasts, and SSE event streams are hot. Contrast with Cold Publisher.
See also: Sinks.Many, Cold Publisher
M
map
Synchronous 1:1 transformation. The mapping function must not perform I/O, block, or return a publisher. If it does, use flatMap instead. Using map when the function returns a Mono produces Flux<Mono<T>> — a stream of unsubscribed publishers.
Mono
Project Reactor's publisher of 0 or 1 item. The reactive equivalent of Optional but asynchronous. Use for: single-resource lookups, POST/PUT operations, fire-and-forget (Mono<Void>). Terminates with onNext+onComplete (item present), onComplete alone (empty), or onError.
See also: Flux, Publisher
O
onErrorResume
Catches an error signal and switches to a fallback publisher. The error is consumed — it does not propagate further. The fallback can be async (another DB lookup, another service call). Use type-targeted overload: .onErrorResume(SpecificException.class, fn) to leave other exceptions unhandled.
Operator
A function that takes a publisher, transforms it, and returns a new publisher without subscribing. Operators are lazy and composable — they build a description of a pipeline. No work is done until subscription. Examples: map, flatMap, filter, retry.
P
parallel Scheduler
A Reactor scheduler backed by a fixed pool of CPU-count threads. Designed for non-blocking, CPU-bound work (transformations, crypto, serialisation). Do NOT use for blocking I/O — use boundedElastic for that.
Processor
A Reactive Streams component that is both a Publisher and a Subscriber. Reactor has deprecated raw Processor usage; the modern replacement is Sinks.Many or Sinks.One.
Publisher
The Reactive Streams interface with a single method: subscribe(Subscriber). Both Mono and Flux implement Publisher<T>. A Publisher is a lazy description of a computation — it does nothing until subscribed.
publishOn
Switches the execution thread for all downstream operators from the point of insertion to the next publishOn or end of chain. Multiple publishOn calls in one pipeline are valid and switch threads at each point. Contrast with subscribeOn.
R
R2DBC
Reactive Relational Database Connectivity — the non-blocking SQL driver spec. Replaces JDBC in reactive stacks. Spring Data R2DBC provides repositories extending ReactiveCrudRepository<T, ID>. Note: no lazy loading, no @OneToMany — joins require explicit reactive queries.
Reactive Streams Specification
A 4-interface Java specification (Publisher, Subscriber, Subscription, Processor) defining asynchronous, backpressure-capable streaming. Implemented by Project Reactor, RxJava, Akka Streams, and incorporated into Java 9 as java.util.concurrent.Flow.
retry / retryWhen
.retry(n) re-subscribes to the upstream n times on any error. .retryWhen(Retry.backoff(n, duration)) adds exponential backoff, jitter, and per-exception filtering. Important: retry replays the ENTIRE upstream chain including source creation — scope it tightly around the operation that can fail.
S
Sinks.Many
Reactor's thread-safe programmatic publisher. Replaces the deprecated FluxProcessor. Use Sinks.many().multicast() to push events from imperative code into a reactive Flux (e.g. from a REST endpoint into a Service Bus publisher). Always use tryEmitNext() from concurrent code.
See also: Hot Publisher
StepVerifier
Reactor Test DSL for asserting publisher behavior. Subscribes to the publisher and lets you declare expected items, errors, and completion in sequence. Blocks until the stream terminates. Use withVirtualTime() for time-based tests (retry delays, timeouts) without real waiting.
subscribeOn
Specifies the Scheduler on which the subscription (source creation) executes. Only the first subscribeOn in a chain has effect. Used to move a blocking source (legacy JDBC, file I/O) off the event-loop thread onto a boundedElastic pool. Contrast with publishOn.
subscribe()
The terminal operation that triggers execution of a reactive pipeline. A pipeline with no subscriber never executes. In Spring WebFlux, you return the publisher from the controller and the framework calls subscribe() for you. Never call subscribe() directly inside a reactive chain — use flatMap or then() instead.
Subscription
The link between a Publisher and a Subscriber. Created during onSubscribe(). The Subscriber calls subscription.request(n) to pull n items — this is the backpressure signal. The Subscriber calls subscription.cancel() to stop receiving items and release resources.
switchIfEmpty
Replaces an empty publisher with a fallback publisher. Useful pattern: repo.findById(id).switchIfEmpty(Mono.error(new NotFoundException(id))) — converts "not found" (empty) into a domain error. The fallback is lazy: it's only subscribed if the original emits nothing.
W
WebClient
Spring's non-blocking HTTP client. Returns Mono<T> or Flux<T>. Replaces RestTemplate in reactive stacks. Supports .retrieve().bodyToMono(T) for single responses and .bodyToFlux(T) for streaming NDJSON. Can be configured with retry, timeout, and error mapping.
WebFlux
Spring's reactive web framework. Runs on Netty (non-blocking event loop) instead of Tomcat. Controllers return Mono<T> or Flux<T>. Spring subscribes to the returned publisher — you never call .subscribe() in a controller. Requires spring-boot-starter-webflux, not spring-boot-starter-web.
Z
zip / zipWith
Mono.zip(a, b) subscribes to both publishers simultaneously and emits a Tuple2 when both complete. The total latency is max(a, b), not a + b. Use for parallel independent lookups. On a Flux, zipWith pairs items by position — stops when the shorter Flux completes.
