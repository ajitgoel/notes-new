Approach 1: Spring Cloud Stream Binder (Recommended)

The simplest way. Spring Cloud Azure's Service Bus binder maps Consumer<Flux<T>> and Supplier<Flux<T>> beans to Service Bus topics automatically.

Dependencies

<!-- pom.xml -->
<dependency>
  <groupId>com.azure.spring</groupId>
  <artifactId>spring-cloud-azure-stream-binder-servicebus</artifactId>
</dependency>
<dependency>
  <groupId>org.springframework.cloud</groupId>
  <artifactId>spring-cloud-stream</artifactId>
</dependency>

application.yml

spring:
  cloud:
    azure:
      servicebus:
        connection-string: ${AZURE_SERVICE_BUS_CONNECTION_STRING}
    stream:
      bindings:
        publishRxEvent-out-0:
          destination: rx-events
        processRxFilled-in-0:
          destination: rx-filled
          group: fill-service-sub
      servicebus:
        bindings:
          processRxFilled-in-0:
            consumer:
              max-concurrent-calls: 10
              max-concurrent-sessions: 5

Publisher: Supplier<Flux<T>>

@Configuration
public class RxEventPublisher {

    // Sinks.Many is a hot publisher — push events into it from anywhere
    private final Sinks.Many<RxEvent> sink =
        Sinks.many().multicast().onBackpressureBuffer(1000);

    // Spring Cloud Stream calls this to get the Flux to publish
    @Bean
    public Supplier<Flux<RxEvent>> publishRxEvent() {
        return sink::asFlux;
    }

    // Call this from your service layer to emit an event
    public Mono<Void> emit(RxEvent event) {
        return Mono.fromRunnable(() -> {
            Sinks.EmitResult result = sink.tryEmitNext(event);
            if (result.isFailure()) {
                throw new RuntimeException("Emit failed: " + result);
            }
        });
    }
}

Consumer: Consumer<Flux<T>>

@Configuration
public class RxFilledConsumer {

    private final InventoryService inventorySvc;

    // Spring Cloud Stream injects the Flux from Service Bus
    @Bean
    public Consumer<Flux<Message<RxFilledEvent>>> processRxFilled() {
        return messages -> messages
            .flatMap(
                msg -> handleFilled(msg.getPayload())
                    .// Acknowledge on success, dead-letter on failure
                    doOnSuccess(v -> ack(msg))
                    .onErrorResume(ex -> {
                        log.error("Process failed, dead-lettering: {}", msg.getPayload(), ex);
                        deadLetter(msg, ex.getMessage());
                        return Mono.empty();
                    }),
                10  // concurrency — matches max-concurrent-calls in yml
            )
            .subscribe();
    }

    private Mono<Void> handleFilled(RxFilledEvent event) {
        return inventorySvc.decrementStock(event.getNdc(), event.getQuantity())
            .flatMap(updated -> updated.isLow()
                ? alertSvc.sendLowStockAlert(updated)
                : Mono.empty());
    }
}

Approach 2: Raw Service Bus SDK (for custom control)

When you need fine-grained control over sessions, DLQ processing, or scheduling — use the SDK directly:

@Service
public class ServiceBusReactiveClient {

    private final ServiceBusSenderAsyncClient sender;
    private final ServiceBusReceiverAsyncClient receiver;

    public Mono<Void> send(RxEvent event) {
        ServiceBusMessage msg = new ServiceBusMessage(serialize(event))
            .setContentType("application/json")
            .setSubject(event.getType())
            .setMessageId(event.getId().toString());

        return sender.sendMessage(msg)
            .retryWhen(Retry.backoff(3, Duration.ofMillis(500)));
    }

    public Flux<ServiceBusReceivedMessage> receive() {
        return receiver.receiveMessages()
            .// Process with bounded concurrency
            flatMap(msg -> process(msg)
                .flatMap(ok -> receiver.complete(msg))
                .onErrorResume(ex -> receiver.deadLetter(msg,
                    new DeadLetterOptions()
                        .setDeadLetterReason(ex.getMessage()))),
                10
            );
    }

    public Mono<Void> scheduleMessage(RxEvent event, OffsetDateTime at) {
        ServiceBusMessage msg = new ServiceBusMessage(serialize(event));
        return sender.scheduleMessage(msg, at).then();
    }
}
Sinks.Many — Bridging Imperative to Reactive
Sinks.Many<T> is Reactor's thread-safe way to programmatically push items into a Flux from imperative code (e.g. a REST endpoint that triggers an event). Think of it as a reactive queue you can push into from anywhere. Use tryEmitNext() — never emitNext() from concurrent threads.

Sinks.many().unicast()

Only one subscriber. Fast — no fan-out overhead. Use for pipeline hand-off between two components.

Sinks.many().multicast()

Multiple subscribers see the same items. Use for fan-out (e.g. audit log + inventory update both receive rx-filled events).
