Lesson 02 / 08 Core Operators: map, flatMap, filter, zip

Operators are the vocabulary of reactive programming. They are pure functions that transform, filter, or combine streams without ever subscribing themselves. This lesson covers the four you'll use in 80% of your Empower PMS pipelines.

.map() Synchronous 1:1 transformation

map applies a synchronous function to each item. The function returns a plain value — not a publisher.

source
rx1
rx2
rx3
|
.map(rx -> rx.getPatientName().toUpperCase())
output
A
B
C
|
// Pharmacy example: transform Prescription to DTO
Flux<Prescription> prescriptions = repo.findByPatientId(patientId);

Flux<PrescriptionDTO> dtos = prescriptions
    .map(rx -> new PrescriptionDTO(
        rx.getId(),
        rx.getDrugName(),
        rx.getPatient().getName().toUpperCase()
    ));

// .map() is synchronous — function MUST NOT block
// If your function does I/O → use flatMap instead
.flatMap() Async 1:N transformation — the workhorse

flatMap is what you use when your transformation returns a Mono or Flux. It subscribes to each inner publisher and merges the results. Results may arrive out of order (subscriptions are concurrent).

source
rx1
rx2
.flatMap(rx -> drugInteractionService.check(rx)) // returns Mono<CheckResult>
output
r2
r1
|

rx2 completed first — order is NOT guaranteed with flatMap

// Pharmacy: for each prescription, check drug interactions (async I/O)
Flux<CheckResult> results = prescriptions
    .flatMap(rx -> drugInteractionService.check(rx));
// All checks run CONCURRENTLY — rx2 result may arrive before rx1

// Chaining multiple async steps:
Mono<FillConfirmation> fill = patientRepo.findById(patientId)
    .flatMap(patient -> formularyService.checkCoverage(patient, ndc))
    .flatMap(coverage -> rxRepo.save(buildPrescription(coverage)))
    .flatMap(saved -> eventBus.publish(new RxFilledEvent(saved)));

// Use flatMapSequential() to preserve order at the cost of some concurrency
The #1 Mistake
Using .map() when your lambda returns a Mono/Flux. You'll get Flux<Mono<Patient>> — a stream of unwrapped publishers. The inner mono never gets subscribed. Always use .flatMap() when your function does I/O.
.filter() Conditional pass-through

filter passes only items matching a predicate. Items not matching are silently dropped — the stream continues. On a Mono, a false predicate produces Mono.empty().

// Only process controlled substances (DEA schedule II-V)
Flux<Prescription> controlled = prescriptions
    .filter(rx -> rx.getDeaSchedule() != null);

// On Mono — filter turns it into Mono.empty() if predicate fails
Mono<Patient> activePatient = patientRepo.findById(id)
    .filter(Patient::isActive);
// If patient exists but is inactive → empty Mono (no error thrown)

// Combine with switchIfEmpty to handle the empty case:
activePatient
    .switchIfEmpty(Mono.error(new PatientInactiveException(id)));
.zipWith() / Mono.zip() Combine two streams element-by-element

zip waits for an item from each source, then combines them. Perfect for parallel independent lookups that you need to combine before proceeding.

// Fetch patient AND formulary coverage IN PARALLEL, then combine
Mono<Patient> patientMono   = patientRepo.findById(patientId);
Mono<Coverage> coverageMono = formularyService.getCoverage(patientId);

Mono<FillRequest> combined = Mono.zip(patientMono, coverageMono)
    .map(tuple -> new FillRequest(tuple.getT1(), tuple.getT2(), ndc));
// Both lookups execute CONCURRENTLY — total time = max(patient, coverage) not sum

// zipWith on a Flux — pairs items positionally
Flux<String> names  = Flux.just("Alice", "Bob");
Flux<String> drugs  = Flux.just("Lisinopril", "Metformin");

names.zipWith(drugs)
    .map(t -> t.getT1() + " takes " + t.getT2())
    .subscribe(System.out::println);
// "Alice takes Lisinopril"
// "Bob takes Metformin"

Other Essential Operators

// switchIfEmpty — fallback when Mono/Flux produces nothing
patientRepo.findById(id)
    .switchIfEmpty(Mono.error(new NotFoundException("Patient " + id)));

// doOnNext — side-effect logging (does NOT transform)
prescriptions
    .doOnNext(rx -> log.info("Processing rx={}", rx.getId()))
    .flatMap(this::processPrescription);

// take / skip — pagination or bounded streams
Flux<Prescription> page = allRx.skip(20).take(10);

// collectList — materialise a Flux into Mono<List>
Mono<List<Prescription>> allAsList = prescriptions.collectList();

// merge vs concat
Flux.merge(flux1, flux2);   // subscribe to both CONCURRENTLY, interleave
Flux.concat(flux1, flux2);  // flux1 completes THEN flux2 starts

Complete Pipeline: Rx Fill Workflow

Here's the full Empower PMS prescription fill pipeline using everything in this lesson:

@Service
public class PrescriptionFillService {

    public Mono<FillConfirmation> fill(Long patientId, String ndc, int qty) {

        // Step 1: fetch patient and coverage in parallel
        Mono<Patient>  patient  = patientRepo.findById(patientId)
            .filter(Patient::isActive)
            .switchIfEmpty(Mono.error(new InactivePatientException(patientId)));

        Mono<Drug>     drug     = drugRepo.findByNdc(ndc)
            .switchIfEmpty(Mono.error(new DrugNotFoundException(ndc)));

        // Step 2: zip the two parallel lookups
        return Mono.zip(patient, drug)

            // Step 3: async drug interaction check
            .flatMap(t -> interactionSvc.check(t.getT1(), t.getT2())
                .map(ok -> new FillRequest(t.getT1(), t.getT2(), qty)))

            // Step 4: persist
            .flatMap(rxRepo::save)

            // Step 5: emit event (fire and forget)
            .flatMap(saved -> eventBus
                .publish(new RxFilledEvent(saved))
                .thenReturn(saved))

            // Step 6: map to response DTO
            .map(FillConfirmation::from)

            // Step 7: log each step for audit
            .doOnNext(conf -> auditLog.record(conf));
    }
}
