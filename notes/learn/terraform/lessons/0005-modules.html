Modules:
Reusable Infrastructure

How to structure Terraform into reusable, composable units — the difference between a root module and a child module, and the layout patterns used in production.

🧩 What Is a Module?

Every Terraform directory is a module. The one you run terraform apply in is the root module. Any module it calls is a child module. Modules let you package a group of resources into a reusable unit with a clean input/output interface.

Root Module

The entry point. Has the backend config, provider declarations, and calls child modules. One per environment (dev/staging/prod).

Child Module

A reusable package — AKS cluster, Key Vault, networking. Has variables.tf, outputs.tf, main.tf. No backend or provider blocks.

🗂️ Production Module Layout

For Empower PMS, a mature layout separates root environments from reusable modules:

empower-infra/
  ├── modules/                    # reusable building blocks
  │   ├── aks/                # AKS cluster module
  │   │   ├── main.tf
  │   │   ├── variables.tf
  │   │   ├── outputs.tf
  │   │   └── versions.tf     # required_providers only
  │   ├── key-vault/
  │   ├── service-bus/
  │   ├── networking/
  │   └── sql-server/
  ├── environments/             # root modules per env
  │   ├── dev/
  │   │   ├── main.tf        # calls modules, wires outputs
  │   │   ├── providers.tf   # backend + provider config
  │   │   └── terraform.tfvars
  │   ├── staging/
  │   └── prod/

📦 Writing a Child Module

Here's the complete structure of an AKS child module — concise but production-quality:

modules/aks/variables.tfvariable "cluster_name"       { type = string }
variable "resource_group_name" { type = string }
variable "location"           { type = string }
variable "kubernetes_version"  { type = string; default = "1.29" }
variable "tags"               { type = map(string); default = {} }

variable "default_node_pool" {
  type = object({
    vm_size    = string
    node_count = number
    zones      = optional(list(string), ["1", "2", "3"])
  })
}
modules/aks/main.tfresource "azurerm_kubernetes_cluster" "this" {
  name                = var.cluster_name
  location            = var.location
  resource_group_name = var.resource_group_name
  kubernetes_version  = var.kubernetes_version
  dns_prefix          = var.cluster_name
  tags                = var.tags

  default_node_pool {
    name       = "system"
    vm_size    = var.default_node_pool.vm_size
    node_count = var.default_node_pool.node_count
    zones      = var.default_node_pool.zones
    upgrade_settings { max_surge = "33%" }
  }

  identity { type = "SystemAssigned" }

  network_profile {
    network_plugin = "azure"
    network_policy = "calico"
  }
}
modules/aks/outputs.tfoutput "cluster_id"                { value = azurerm_kubernetes_cluster.this.id }
output "kubelet_identity_object_id" { value = azurerm_kubernetes_cluster.this.kubelet_identity[0].object_id }
output "kube_config"               { value = azurerm_kubernetes_cluster.this.kube_config_raw; sensitive = true }

🔌 Calling a Module

From the root module, call child modules with a module block. Wire outputs to inputs:

environments/dev/main.tfmodule "networking" {
  source = "../../modules/networking"

  name_prefix         = local.name_prefix
  resource_group_name = azurerm_resource_group.main.name
  location            = var.location
  tags                = local.common_tags
}

module "aks" {
  source = "../../modules/aks"

  cluster_name        = "aks-empower-dev"
  resource_group_name = azurerm_resource_group.main.name
  location            = var.location
  tags                = local.common_tags

  default_node_pool = {
    vm_size    = "Standard_D4s_v3"
    node_count = 2
  }
}

module "key_vault" {
  source = "../../modules/key-vault"

  name                = "kv-empower-dev"
  resource_group_name = azurerm_resource_group.main.name
  location            = var.location
  # Wire AKS identity to Key Vault access policy
  aks_kubelet_object_id = module.aks.kubelet_identity_object_id
  tags                  = local.common_tags
}

# Access a child module output
output "aks_cluster_id" {
  value = module.aks.cluster_id
}
Module Source Types

The source argument accepts: ./local/path, ../../relative, git::https://github.com/org/repo//modules/aks, or registry.terraform.io/hashicorp/aks/azurerm. For Empower PMS, local paths in a monorepo is the right starting point.

🔄 Module Versioning with Git Tags

When your modules live in a separate repo, pin to a git tag for stability:

pinned git sourcemodule "aks" {
  source = "git::https://github.com/empower-pharmacy/tf-modules//aks?ref=v1.4.2"
  # Note: double-slash separates repo path from subdirectory
}
After adding/changing a module source

Always run terraform init again after changing a source argument. Terraform needs to download or refresh the module. The -upgrade flag forces refresh of cached modules.
