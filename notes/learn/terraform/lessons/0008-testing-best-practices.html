Testing, Linting &
Best Practices

How to validate, lint, and test your Terraform before it touches production — from fast static checks to full integration tests that provision real infrastructure.

🔬 The Testing Pyramid

Terraform testing has four tiers, ordered by speed and cost. Run all of them in CI; run the fast ones locally before every push:

⚡
Static Analysis
fmt, validate, tflint, checkov
seconds · free
📋
Plan Testing
terraform plan + OPA / conftest policies
minutes · free
🧪
Unit Tests
terraform test (HCL-native, TF 1.6+)
minutes · low cost
🌐
Integration Tests
Terratest (Go) — real infra, real APIs
30–60 min · Azure cost

⚡ Tier 1: Static Analysis

These run in seconds and catch most issues before anything touches Azure:

Makefile — local dev workflowlint:
	terraform fmt -recursive -check .
	terraform validate
	tflint --recursive
	checkov -d . --framework terraform --compact

fix:
	terraform fmt -recursive .

# Run before every commit:
# make lint && git add -A && git commit -m "feat: add sql module"
.tflint.hcl — tflint configplugin "azurerm" {
  enabled = true
  version = "0.26.0"
  source  = "github.com/terraform-linters/tflint-ruleset-azurerm"
}

rule "terraform_naming_convention" { enabled = true }
rule "terraform_documented_variables" { enabled = true }
rule "terraform_documented_outputs" { enabled = true }
rule "azurerm_resource_missing_tags" {
  enabled  = true
  tags     = ["Environment", "ManagedBy", "CostCenter"]
}
checkov — security scanning

Checkov is a policy-as-code scanner. It ships with 1,000+ Azure checks out of the box: things like "Key Vault must have purge protection", "SQL Server must have TLS 1.2", "AKS must have RBAC enabled". Run it in CI as a gate for every PR.

📋 Tier 2: Plan Policy Enforcement (OPA / Conftest)

Run terraform plan -out=tfplan.binary, convert to JSON, then enforce policies with Open Policy Agent. This is how you prevent devs from accidentally deploying prod-only resources to dev:

policy/deny_public_sql.regopackage terraform

deny[msg] {
  r := input.resource_changes[_]
  r.type == "azurerm_mssql_server"
  r.change.after.public_network_access_enabled == true
  msg := sprintf("SQL Server '%s' must not have public network access enabled", [r.address])
}

deny[msg] {
  r := input.resource_changes[_]
  r.type == "azurerm_key_vault"
  r.change.after.purge_protection_enabled == false
  msg := sprintf("Key Vault '%s' must have purge_protection_enabled = true (HIPAA)", [r.address])
}
CI pipeline step — conftest check# Convert binary plan to JSON
terraform show -json tfplan.binary > tfplan.json

# Enforce OPA policies — fails build if any deny rule fires
conftest test tfplan.json --policy policy/

🧪 Tier 3: terraform test (HCL-Native, TF 1.6+)

Terraform 1.6 introduced a native test framework. Write test files in HCL, use run blocks with assert to validate expected values:

tests/key_vault_test.tftest.hclvariables {
  environment = "test"
  location    = "westus2"
}

run "key_vault_sku_is_standard_in_non_prod" {
  command = plan

  assert {
    condition     = azurerm_key_vault.main.sku_name == "standard"
    error_message = "Non-prod environment should use standard SKU"
  }
}

run "key_vault_has_purge_protection" {
  command = plan

  assert {
    condition     = azurerm_key_vault.main.purge_protection_enabled == true
    error_message = "purge_protection_enabled must be true in all environments"
  }
}

run "network_acls_deny_by_default" {
  command = apply   # actually creates the resource

  assert {
    condition     = azurerm_key_vault.main.network_acls[0].default_action == "Deny"
    error_message = "Key Vault must deny all traffic by default"
  }
}
running tests# Run all tests in the tests/ directory
terraform test

# Run a specific test file
terraform test -filter=tests/key_vault_test.tftest.hcl

# Verbose output
terraform test -verbose

🌐 Tier 4: Terratest (Integration)

Terratest (Go library by Gruntwork) deploys real infrastructure, runs assertions, then destroys. Expensive but the highest confidence:

test/aks_test.go (abbreviated)func TestAKSModule(t *testing.T) {
    t.Parallel()

    opts := &terraform.Options{
        TerraformDir: "../modules/aks",
        Vars: map[string]interface{}{
            "environment":   "test",
            "location":      "westus2",
            "cluster_name":  "aks-test-terratest",
        },
    }

    // Destroy at end of test regardless of pass/fail
    defer terraform.Destroy(t, opts)
    terraform.InitAndApply(t, opts)

    clusterID := terraform.Output(t, opts, "cluster_id")
    assert.NotEmpty(t, clusterID)
    assert.Contains(t, clusterID, "/providers/Microsoft.ContainerService")
}

Before merging any Terraform PR

terraform validate — no syntax or type errors
tflint — no linting violations, required tags present
checkov — no HIGH/CRITICAL security findings unaddressed
terraform plan reviewed — someone read the diff, no unexpected destroys
conftest policy checks pass — no deny rules triggered
No secrets in code — sensitive variables use TF_VAR_* or Key Vault references
.terraform.lock.hcl committed — provider versions pinned
terraform.tfstate never committed — .gitignore covers *.tfstate, *.tfstate.backup
All variables documented — description field on every variable block
All outputs documented — description field on every output block
terraform test passes — all .tftest.hcl files green

🏆 Golden Rules

Never edit state manually

Use terraform state mv, state rm, or import. Direct JSON editing corrupts state and is unsupported.

for_each over count for named resources

If the resource has a meaningful name, use for_each with that name as the key. Reserve count for truly numeric/toggle cases.

Pin provider versions

Always use ~> X.Y version constraints. Unpinned providers will drift and break on CI. Commit the lock file.

One state file per environment

Dev, staging, prod each have their own backend key. Never share state between environments.

Small, focused modules

A module should do one thing: AKS, Key Vault, networking. If a module is over 300 lines, split it.

Tags are not optional

Every resource must have Environment, ManagedBy, and CostCenter tags. Enforce with tflint + checkov. Cost allocation depends on it.
