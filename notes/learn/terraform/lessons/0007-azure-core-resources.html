🌐 Networking Foundation

Why it comes first: AKS, SQL, and Key Vault all need subnet IDs. Build the network first and reference it everywhere else.
modules/networking/main.tfresource "azurerm_virtual_network" "main" {
  name                = "vnet-${var.name_prefix}"
  location            = var.location
  resource_group_name = var.resource_group_name
  address_space       = ["10.0.0.0/16"]
  tags                = var.tags
}

resource "azurerm_subnet" "aks" {
  name                 = "snet-aks"
  resource_group_name  = var.resource_group_name
  virtual_network_name = azurerm_virtual_network.main.name
  address_prefixes     = ["10.0.1.0/24"]
}

resource "azurerm_subnet" "data" {
  name                 = "snet-data"
  resource_group_name  = var.resource_group_name
  virtual_network_name = azurerm_virtual_network.main.name
  address_prefixes     = ["10.0.2.0/24"]
  service_endpoints    = ["Microsoft.Sql", "Microsoft.KeyVault"]
}

☸️ AKS Cluster

For Empower PMS: Nine bounded-context microservices (rx-intake, clinical-review, compounding, billing, etc.) running on AKS with Azure CNI for proper VNet integration and pod-level networking.
modules/aks/main.tfresource "azurerm_kubernetes_cluster" "main" {
  name                = "aks-${var.name_prefix}"
  location            = var.location
  resource_group_name = var.resource_group_name
  kubernetes_version  = var.kubernetes_version
  dns_prefix          = "empower-${var.environment}"
  tags                = var.tags

  # System node pool — OS workloads only
  default_node_pool {
    name                = "system"
    vm_size             = var.system_node_vm_size
    node_count          = var.system_node_count
    vnet_subnet_id      = var.aks_subnet_id
    zones               = ["1", "2", "3"]
    os_disk_size_gb     = 128
    type                = "VirtualMachineScaleSets"

    upgrade_settings { max_surge = "33%" }
  }

  # Managed identity — no service principal to rotate
  identity { type = "SystemAssigned" }

  network_profile {
    network_plugin     = "azure"   # Azure CNI: pods get VNet IPs
    network_policy     = "calico"  # NetworkPolicy enforcement
    load_balancer_sku  = "standard"
    service_cidr       = "172.16.0.0/16"
    dns_service_ip     = "172.16.0.10"
  }

  # HIPAA: audit logs to Log Analytics
  oms_agent {
    log_analytics_workspace_id = var.log_analytics_workspace_id
  }

  azure_policy_enabled             = true
  local_account_disabled           = true   # force AAD auth
  role_based_access_control_enabled = true

  azure_active_directory_role_based_access_control {
    managed                = true
    azure_rbac_enabled     = true
    admin_group_object_ids = var.aks_admin_group_ids
  }
}

# User node pool for application workloads
resource "azurerm_kubernetes_cluster_node_pool" "app" {
  name                  = "app"
  kubernetes_cluster_id = azurerm_kubernetes_cluster.main.id
  vm_size               = var.app_node_vm_size
  node_count            = var.app_node_count
  vnet_subnet_id        = var.aks_subnet_id
  zones                 = ["1", "2", "3"]
  mode                  = "User"
  tags                  = var.tags
}
HIPAA note — local_account_disabled

Setting local_account_disabled = true forces all cluster access through Azure AD. This satisfies audit requirements for individual accountability — no shared clusterAdmin credentials.

🔑 Key Vault

For Empower PMS: Stores database passwords, Service Bus connection strings, TLS certificates, and any PHI-adjacent secrets. AKS workloads access secrets via the Secrets Store CSI driver using Managed Identity — no secrets in Kubernetes manifests.
modules/key-vault/main.tfdata "azurerm_client_config" "current" {}

resource "azurerm_key_vault" "main" {
  name                        = "kv-${var.name_prefix}"
  location                    = var.location
  resource_group_name         = var.resource_group_name
  tenant_id                   = data.azurerm_client_config.current.tenant_id
  sku_name                    = var.sku_name   # "premium" in prod
  tags                        = var.tags

  soft_delete_retention_days  = 90
  purge_protection_enabled    = true  # HIPAA: can't permanently delete secrets
  enable_rbac_authorization   = true  # use RBAC, not access policies

  network_acls {
    default_action             = "Deny"
    bypass                     = ["AzureServices"]
    virtual_network_subnet_ids = [var.data_subnet_id]
    ip_rules                   = var.allowed_ip_ranges
  }
}

# Grant AKS kubelet identity access to read secrets
resource "azurerm_role_assignment" "aks_kv_reader" {
  scope                = azurerm_key_vault.main.id
  role_definition_name = "Key Vault Secrets User"
  principal_id         = var.aks_kubelet_object_id
}

📨 Service Bus

For Empower PMS: Service Bus is the backbone of the saga pattern across rx-intake → clinical-review → compounding → dispensing. Each bounded context has its own topic/subscription pair.
modules/service-bus/main.tfresource "azurerm_servicebus_namespace" "main" {
  name                = "sb-${var.name_prefix}"
  location            = var.location
  resource_group_name = var.resource_group_name
  sku                 = var.sku   # "Standard" or "Premium"
  tags                = var.tags

  # Premium required for VNet integration and private endpoints
  zone_redundant = var.sku == "Premium" ? true : false
}

# One topic per domain event stream
resource "azurerm_servicebus_topic" "topics" {
  for_each = toset(var.topic_names)

  name         = each.value
  namespace_id = azurerm_servicebus_namespace.main.id

  default_message_ttl              = "P14D"   # 14-day message TTL
  max_size_in_megabytes            = 5120
  requires_duplicate_detection     = true
  duplicate_detection_history_time = "PT10M"
}

# Each consumer service gets its own subscription
resource "azurerm_servicebus_subscription" "subs" {
  for_each = var.subscriptions   # map: "topic/consumer" => config

  name               = each.value.consumer_name
  topic_id           = azurerm_servicebus_topic.topics[each.value.topic].id
  max_delivery_count = 10
  dead_lettering_on_message_expiration = true
  lock_duration      = "PT5M"
}
calling the service-bus module — dev rootmodule "service_bus" {
  source = "../../modules/service-bus"

  name_prefix         = local.name_prefix
  resource_group_name = azurerm_resource_group.main.name
  location            = var.location
  sku                 = "Standard"
  tags                = local.common_tags

  topic_names = [
    "prescription-received",
    "clinical-review-completed",
    "compounding-started",
    "dispensing-completed"
  ]

  subscriptions = {
    "rx-clinical" = { topic = "prescription-received",      consumer_name = "clinical-review" }
    "clinical-comp" = { topic = "clinical-review-completed", consumer_name = "compounding" }
    "comp-disp" = { topic = "compounding-started",          consumer_name = "dispensing" }
  }
}

🗄️ SQL Server

For Empower PMS: Central SQL Server instance with per-service databases. Admin password injected from Key Vault at plan time. VNet service endpoint restricts access to the data subnet only.
modules/sql-server/main.tfresource "azurerm_mssql_server" "main" {
  name                          = "sql-${var.name_prefix}"
  resource_group_name           = var.resource_group_name
  location                      = var.location
  version                       = "12.0"
  administrator_login           = var.admin_login
  administrator_login_password  = var.admin_password   # sensitive var
  minimum_tls_version           = "1.2"
  public_network_access_enabled = false   # VNet only
  tags                          = var.tags

  azuread_administrator {
    login_username = "aks-admin-group"
    object_id      = var.aad_admin_group_object_id
  }
}

# One database per bounded context
resource "azurerm_mssql_database" "dbs" {
  for_each  = toset(var.database_names)
  name      = each.value
  server_id = azurerm_mssql_server.main.id
  sku_name  = var.db_sku   # "S3" dev, "P2" prod
  tags      = var.tags
}

# Lock down to data subnet only
resource "azurerm_mssql_virtual_network_rule" "data_subnet" {
  name      = "allow-data-subnet"
  server_id = azurerm_mssql_server.main.id
  subnet_id = var.data_subnet_id
}

# HIPAA: enable auditing to storage account
resource "azurerm_mssql_server_extended_auditing_policy" "main" {
  server_id                               = azurerm_mssql_server.main.id
  storage_endpoint                        = var.audit_storage_endpoint
  retention_in_days                       = 90
  log_monitoring_enabled                  = true
}
HIPAA audit trail pattern

Every resource tier (AKS, SQL, Key Vault, Service Bus) should emit logs to the same Log Analytics Workspace. This gives you a unified audit trail across your entire platform — essential for HIPAA's access logging requirements.

🧠 Knowledge Check

Four questions on Azure resource configuration.

1. Why is purge_protection_enabled = true important for Key Vault in a HIPAA environment?

A. It prevents secrets from being read by unauthorized users
B. It encrypts secrets at rest
C. It prevents permanent deletion of secrets — ensuring you can't destroy audit-relevant key material, even with privileged access
D. It enables automatic key rotation

2. What is the purpose of service_endpoints = ["Microsoft.Sql", "Microsoft.KeyVault"] on a subnet?

A. Installs SQL Server and Key Vault on the subnet
B. Routes traffic to those Azure services over the Microsoft backbone network, enabling VNet rules to restrict access to that subnet
C. Opens firewall ports 1433 and 443 on the subnet
D. Enables Private Endpoints for those services

3. AKS is configured with network_plugin = "azure" (Azure CNI). What does this give you over kubenet?

B. Pods get real VNet IP addresses — enabling network policies, direct pod-to-service communication, and VNet integration with SQL/Key Vault
A. Better performance because it uses a kernel network driver
C. Automatic TLS between pods
D. Pods use NAT through the node IP, reducing address consumption

4. Why use for_each = toset(var.database_names) for SQL databases instead of count?

A. toset() is required for SQL resources — count doesn't work with azurerm_mssql_database
B. Stable string keys (database names) mean adding/removing one DB won't destroy others — count would shift indexes and cause unintended destroys
C. for_each is faster to apply than count
D. No difference — they are equivalent for this use case
